# Diário de bordo — 2026-11-19

Registro pessoal de construção. Não é documentação do projeto (essa está em inglês, na raiz e em `docs/`).

## O que foi construído hoje

- Stack de 11 serviços em duas sub-redes Docker isoladas.
- DNS interno com CoreDNS, incluindo zona `*.local` e forward para a internet.
- Aplicação de três camadas: nginx → API Flask → Postgres.
- Observabilidade: Prometheus, node-exporter, blackbox (HTTP/DNS/TCP), Grafana provisionado, Alertmanager.
- Bot de triagem em Python puro: alerta → ticket agrupado → página HTML.
- 6 alertas, 6 runbooks, 4 ADRs, 2 postmortems e um log de incidentes.
- 4 cenários de caos executados de verdade, com tempo até o ticket medido.
- Screenshots reais e smoke test de 8 checagens.

## O que eu entendi hoje (e preciso conseguir explicar sem olhar)

- O caminho de uma requisição: DNS → TCP → HTTP → nginx → API → Postgres.
- Por que a janela `for` do alerta domina o tempo de detecção.
- Por que inibir `WebDown` quando o DNS cai evita dua páginas para a mesma causa.
- Por que o cliente não alcança o banco: redes Docker isoladas, não VLAN.

## O que ainda me confunde

- Sintaxe de `relabel_configs` no Prometheus (por que `__address__` vira `__param_target`).
- Quando usar inibição e quando usar silêncio.
- Como o `tc netem` afeta só a saída do container.
